# 🔐「O中の封印を解け！」謎解きサイト

8/9（日）親子学び祭「全体レクリ（脱出ゲーム）」用の、QR連動謎解きWebサイトです。
静的サイト（GitHub Pages）＋ Google Apps Script（GAS）＋スプレッドシートで動きます。
サーバーの常時運用は不要・すべて無料枠です。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 参加者用トップ（チーム登録・進捗★表示・番号手動入力） |
| `point.html` | 謎画面（QRの飛び先。鍵謎→正解後に在り処謎を表示） |
| `dashboard.html` | 運営用ダッシュボード（全チームの段階・進捗・ヒント状況を一覧、10秒ごと自動更新。中謎5問／扉の謎／最後の謎まで追える） |
| `js/puzzles.js` | **謎データ**（問題文・4択・正解・鍵の数字・ヒント・在り処謎）。差し替えはこのファイルだけでOK |
| `js/config.js` | サイト設定（GASのURL・自動ヒントの秒数など） |
| `js/store.js` | 進捗の保存（スマホ内）とGASへの送信 |
| `css/style.css` | デザイン |
| `gas/Code.gs` | GASバックエンドのコード（スプレッドシートに貼り付けて使う） |
| `tools/qr.html` | 設置用QRコードの一括生成・印刷ツール（運営用） |

## セットアップ手順（全部で15分くらい）

### 1. GAS（データ保存先）のセットアップ — コピペ4ステップ

1. [Googleスプレッドシート](https://sheets.new) を新規作成し、名前を「封印を解け_記録」などにする
2. メニューの **拡張機能 → Apps Script** を開き、最初から入っているコードを全部消して、
   このリポジトリの `gas/Code.gs` の中身を丸ごと貼り付ける
3. コード冒頭の `ADMIN_KEY = "oyakomanabi"` を**自分だけが知る合言葉に変更**して保存（Ctrl+S）
4. 右上の **デプロイ → 新しいデプロイ** を押し、
   - 種類の選択（⚙アイコン）→ **ウェブアプリ**
   - 「次のユーザーとして実行」→ **自分**
   - 「アクセスできるユーザー」→ **全員**
   - デプロイを押す（初回は「アクセスを承認」でGoogleアカウントの許可が必要。
     「このアプリは確認されていません」と出たら「詳細」→「（無題のプロジェクト）に移動」で進めてOK）
   - 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/～/exec`）をコピー

> ⚠️ `Code.gs` を修正したときは、**デプロイ → デプロイを管理 → ✏編集 → バージョン「新バージョン」→ デプロイ** をしないと反映されません（URLは変わりません）。

### 2. サイト側の設定

`js/config.js` の `GAS_URL: ""` に、↑でコピーしたURLを貼り付ける。

```js
GAS_URL: "https://script.google.com/macros/s/XXXX/exec",
```

### 3. GitHub Pages で公開

1. GitHubのリポジトリページ → **Settings → Pages**
2. Source を「Deploy from a branch」、Branch を公開したいブランチ・`/(root)` にして Save
3. 数分後に `https://ユーザー名.github.io/ManabiMatsuri/` で公開される

### 4. QRコードの印刷

公開したサイトの `tools/qr.html` をPCで開き、サイトのURLを入力して「生成」→「印刷」。
5か所分のQRコード（手動入力用の番号つき）がまとめて印刷できます。

### 5. 動作確認

- スマホで公開URLを開く → チーム登録 → QR（または番号入力）で謎画面 → 正解 → ★が増える
- PCで `dashboard.html` を開き、合言葉（ADMIN_KEY）を入れる → テストしたチームが表示されればOK
- スプレッドシートの `events` シートに記録が増えていることも確認

## 謎の差し替え方法

`js/puzzles.js` を開き、各ポイントの以下を書き換えるだけです（コードの知識は不要）：

- `question` … 鍵謎の問題文（`\n` で改行）
- `choices` … 4択の選択肢（4つ。数字の1〜4で統一）
- `answerIndex` … 正解の番号（0=1, 1=2, 2=3, 3=4）。正解時に表示される「鍵の数字」は `choices[answerIndex]` の値がそのまま使われる（③大謎の計算で使う数字）
- `smallHint` … 小ヒント（答えに直結しない手がかり程度に）
- `arikaImage` … 在り処謎の画像（次の場所への誘導。鍵謎に正解するまで表示されません。テキストの説明文はなし・画像のみ）
- `place` … 場所の覚え書き。**参加者の画面には出ません。** QR印刷ツールと運営の進行画面でだけ使います（場所は在り処謎の画像が示すため）
- `arikaHint` … 在り処謎のヒント（文章）。ヒントボタンを押すまで出ません
- `arikaHintIsImage` … `true` にすると、`arikaImage` の**下半分**をヒント（五十音表など）として扱います。ふだんは上半分だけを見せ、ヒントボタンを押したときだけ下半分を見せます。謎画面（`point.html`）でもホームの「次に向かう場所」でも同じ扱いになります（`js/arika.js`）

画像を使いたい場合は `images/` フォルダに `KeyA.png`〜`KeyE.png`（鍵謎の画像）、`PlaceA.png`〜`PlaceE.png`（在り処謎の画像）を入れる。

## 当日の運用

- **スタートの流れ**：①オープニングで小謎プリントを配布 → ②解けた参加者が運営に提出 → ③運営が**スタートQR**（`tools/qr.html`で印刷、①〜⑤の5種をランダムに）を渡す → ④読み込むと「手紙の続き」＋最初の在り処謎が表示される
- **参加者**：在り処謎の場所へ → QR読み取り → 謎を解く → 在り処謎で次へ → 5つ集めて封印解除
- **運営**：`dashboard.html` を開いておく
  - 🔴 赤い行 ＝ まだ解けていない謎でヒントを見ているチーム。「◯◯で12分経過」のように表示されるので、長いチームから様子を見に行く（仕様どおり、システムからの強制ネタバレはありません）。中謎5問だけでなく、**扉の謎と最後の謎のヒントも赤くなります**
  - 「いまどこ」の列は **鍵あつめ → 扉の謎 → 最後の謎 → 完全クリア** の順に進みます。鍵あつめ中は最後に読み取ったQRの場所が出ます
  - 最後の謎の 🌙🔑 は、ホームの2つの仕掛けを見つけたかどうか。薄い印はまだ見つけていない状態なので、片方だけで止まっているチームが分かります
  - 「誤答」は中謎5問・扉の謎・最後の謎の合計回数です
  - ⚠ 扉の謎と最後の謎の集計は `gas/Code.gs` 側にも手を入れています。**GASを貼り替えて再デプロイしないと、この2つの段階は出ません。** 貼り替えがまだのときは、ダッシュボードの上に赤い注意書きと手順が出るので、それが消えれば完了です
    - 貼り替えの判定は `gas/Code.gs` 冒頭の `BACKEND_VERSION` で行っています
    - **この貼り替えは1回だけで済みます。** GAS はイベントの種類を決め打ちせず、来たものを種類ごとに数えて返すだけ（`team.types`）にしてあります。今後 謎や仕掛けを足して新しい種類のイベントを送るようになっても、意味づけは `dashboard.html` 側だけで完結するので、GAS を触る必要はありません
    - 集計はスプレッドシートの全行を毎回読み直しています。そのため**イベントの途中や後に貼り替えても、それまでの記録がさかのぼって反映されます**（取りこぼしにはなりません）
- **ヒント**：ヒントボタン押下のほか、謎画面を開いて **3分**（`config.js` の `AUTO_HINT_SECONDS` で変更可）経つと小ヒントが自動表示されます
- **QRが読めない参加者**：トップページの番号入力（1〜5）から同じ謎に入れます
- **謎の内容だけ確認したいとき（デバッグ用）**：チーム登録なしで `point.html?p=番号&debug=1` を直接開くと表示できます（例：`point.html?p=3&debug=1`）。記録は一切送信されません
- **好きなところまで飛ばしたいとき（デバッグ用）**：`index.html?debug=1` を開くと「🔧 好きなところまで飛ばす」が出ます。**最初から**（記録を消す）／**扉謎の前**（鍵5つそろった状態）／**扉謎のあと**（最後の謎に挑める状態）／**最後の謎のあと**（すべてクリア）の4つ。端末の記録を書き換えるだけで、集計には何も送りません。動作確認のたびに謎を解き直す必要がなくなります
- **本番前にデバッグ機能を一括オフにする**：`js/config.js` の `DEBUG_ENABLED: true` を `false` に変えるだけで、`?debug=1` によるプレビューや `final.html` の「デバッグ用」ボタンなど、サイト全体のデバッグ機能が使えなくなります（コードの他の部分は一切触らなくてOK）

## データについての注意

- 進捗は各スマホの localStorage にも保存されるため、**通信が不安定でも参加者のプレイは止まりません**（記録の送信は非同期・失敗しても無視して続行）
- 氏名を含む記録はスプレッドシートに残ります。**イベント終了後にスプレッドシートを削除**してください（事前説明済みの個人情報対応）
- 4択の正解は `js/puzzles.js` に平文で入っています。ブラウザのソース表示で見ようと思えば見えますが、校内イベントの性質上、許容範囲としています（気になる場合は相談してください）

## ③大謎（最後の謎）— `secret.html`

扉の謎（`final.html`）をクリアすると、4通目の手紙の下に
**「→ 「学校の秘密」を探しに行く」** ボタンが出て、この画面に進みます。
5つの鍵がそろうと扉謎のボタンが出るのと同じ仕組みです。

Xも答えを知らない謎、という設定なので、参加者がその日見つけたものを
合言葉として入力します。

### 封印を解く手順（2つの隠しギミック）

この画面に入ると、まずXの手紙と**2つの指示文**が出ます。
指示文は「①②」ではなく、現れる謎と同じ呼び名（**月の謎 / 鍵の謎**）で出します。

```
月の謎 ― 動かぬ月、鍵のかかった魔法陣の中心に来たるとき
鍵の謎 ― 浮かび上がる「鍵」に三度触れるとき
```

それぞれがそのまま操作の説明になっていて、達成すると謎が1つずつ現れます。
現れた謎のカードには、その入口になった指示文（`SECRET_PUZZLES.*.instruction`）も
一緒に出るので、「何をしたら出てきたのか」を見失いません。
2つとも現れると、合言葉の入力欄が出ます。

| 指示文 | 操作 | 現れる謎 |
|---|---|---|
| 月の謎 | 画面右上の月を、魔法陣の中心までドラッグする | `SECRET_PUZZLES.moon`（**初めに受け取った魔法陣**＝一通目の手紙にパンフレットを重ねる。答え：おやこ） |
| 鍵の謎 | 背景を漂う「鍵」の文字を3回タップする | `SECRET_PUZZLES.key`（謎解きシートの果物をそろえて解き直す。答え：がっこう） |

「初め」に受け取ったもの（一通目の手紙）へ戻る謎を、**初め側の指示文＝月の謎**に
割り当ててあります。

- 指示文の意味がわからない参加者向けのボタン（`SECRET_GIMMICK_HINT`）は、
  答えを明かさず「近くの魔法使いに声をかけてみよう」と案内します。
- 進捗は `team.secretGate.foundMoon` / `foundKey` に保存されるので、
  途中で画面を閉じても現れた謎は消えません。
- 「鍵」は**見えているとき（不透明度0.25以上）だけ**反応します。
  消えかけを連打してもカウントされません。

どちらの謎文も `js/puzzles.js` の `SECRET_PUZZLES` にあります。`image` に
画像パスを入れると謎の画像も出せます。合言葉は入力する順番を問わないので、
月・鍵のどちらがどちらの言葉を導いても成立します。

### クリア後の「はじめから遊びなおす」

封印を解いた**あとにだけ**、`secret.html` のクリア画面とホームに
🔄 **はじめから遊びなおす** が出ます（`#replayCard`）。おうちに帰ってから
家族ともう一度遊べるようにするためのものです。

- デバッグ用のリセットとは別物で、クリアするまでは現れません
- 押すと2度押しの確認をはさんでから、端末の記録（`Store.KEY` と
  `fuin_letter_seen`）だけを消し、`letter.html` へ送ります
  （手紙の演出からもう一度見せたいため）
- **運営に送った記録（GAS側）には触りません。**ダッシュボードの集計は残ります

**実装メモ**：月とルーン文字は `.scene`（`pointer-events:none`・`z-index:0`）の
中にあるため、そのままでは触れず、カードの裏に隠れてしまいます。かといって
`.scene` 全体を前面に出すと霧やビネットがカードを覆ってしまうので、
対象の2つだけを `#gimmickLayer`（`z-index:60`）へ移し替えています。

### 合言葉

合言葉は**ふたつ**あります。「親子」と「学校」が手を取り合うことが
何より大事、というのがこのイベント全体のテーマなので、片方だけでは開きません。

`js/puzzles.js` の

```js
const SECRET_WORDS = [
  { label: "ひとつめの合言葉", answers: ["おやこ", "親子"] },
  { label: "ふたつめの合言葉", answers: ["がっこう", "学校"] },
];
```

がその答えです。`answers` に書いた表記はどれでも正解になります。
判定は `checkSecretAnswers()` が行い、次のゆれを吸収します。

- ひらがな・漢字・カタカナ（「おやこ」「親子」「オヤコ」すべて可）
- スペース、全角/半角
- **入力する順番**（どちらの欄にどちらを入れても正解）

同じ言葉をふたつの欄に入れた場合は不正解になります。
片方だけ合っているときは「……片方は合ってる。もうひとつは？」と返します。

- ひとつめ「おやこ」… **月の謎**＝パンフレットを一通目の手紙に重ねる謎の答え
- ふたつめ「がっこう」… **鍵の謎**＝謎解きシートの果物をそろえて解き直す謎の答え

ヒントは `SECRET_HINT`、入口のXのことばは `SECRET_CHALLENGE_MESSAGE`、
クリア時のことばは `SECRET_SUCCESS_MESSAGE`、
そのあとに出る最後の手紙は `EPILOGUE` です。

### 一通目の手紙（`PROLOGUE`）を書き換えるときの注意

一通目の手紙には、**16時までに戻ってこいという制限時間**と、
**「貴重品は必ず持って移動してね」**という犯人らしからぬ一言が入っています。
時刻を変えるときは当日の終了時刻に合わせてください（`js/puzzles.js` の `PROLOGUE`）。

> ⚠️ **行数を変えると「おやこ」の謎が壊れます。**
> 手紙は枠に収まるよう自動で縮むので、1行足しただけで文字が小さくなり、
> 3文字（こ・や・お）を結ぶ線の角度も長さも変わります。実際この制限時間の
> くだりを足したときに、角度が 44.27° → 38.02° に変わり、パンフレットに刷る
> 紋章の大きさと位置を取り直しました。
> 文面をいじったら `tools/pamphlet/README.md` の
> 「重ね合わせの謎の座標を作り直す」を最後まで通し、PDFを作り直してください。

### 画面のズームについて（重要）

「おやこ」の謎は、印刷したパンフレットを `letter.html` の手紙に重ねて解きます。
端末ごとに画面の大きさが違うので、**参加者が画面を指で拡大縮小して
紙の大きさを合わせられること**が前提です。ここが効かないと謎が解けません。

そのため、

- 全ページの `<meta name="viewport">` に `user-scalable=yes, maximum-scale=10.0` を明記
- `js/zoom-fix.js`（ページ遷移で前の拡大率が残るiOSの対策）は
  **iOSでのみ・実際に拡大されているときだけ**動き、画面に触れた時点で解除される。
  Android では何もしない（`user-scalable=no` を挟むと、LINE等の内蔵ブラウザで
  拡大できないまま固まることがあるため）
- `letter.html` の読み込みは `data-keep-zoom` を付けて、この対策自体を無効化

としています。**`user-scalable=no` や `maximum-scale=1` を足さないこと。**
`touch-action: none` も、広い範囲に付けるとピンチズームごと殺すので注意
（現在付いているのは、ドラッグする月＝96pxの円だけです）。

さらに保険として、`letter.html` には手紙が開いたあとに
**手動ズームのボタン（－ / ＋ / もどす）** が出ます。ピンチが効かない端末でも
これで紙の大きさを合わせられます（拡大中は指でずらせます）。
